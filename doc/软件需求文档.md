# ScreenRecorderPlayer — 软件需求文档

## 1. 项目概述

### 1.1 项目背景

开发基于 Qt5 (5.15.13) + FFmpeg8 的 Windows 64 位 GUI 应用，实现屏幕录制与视频播放。

### 1.2 项目目标

- 高质量的屏幕录制（无损压缩）
- 流畅的视频播放（OpenGL 渲染）
- 录制与播放互斥
- 简洁的标签页 UI

---

## 2. 技术栈

| 项 | 值 |
|---|---|
| GUI | Qt5 5.15.13 (Widgets, OpenGL, Concurrent) |
| 多媒体 | FFmpeg8 (最新 API，禁用废弃 API) |
| 编译器 | MinGW64 GCC 12 |
| 构建工具 | CMake 3.16 + MinGW Makefiles (mingw32-make) |
| 平台 | Windows x64 |

### 2.1 开发环境约束

| 项 | 约束 |
|---|---|
| IDE | VS Code 或类 VS Code 编辑器，使用 CMake Tools 扩展 |
| 开发平台 | Windows 10/11 x64 |
| 运行平台 | Windows 10/11 x64 |
| 构建器 | MinGW 工具链的 `mingw32-make`（不使用 Ninja） |
| CMake 语法 | 使用现代 target 语法：`add_executable(name)`（无源码）+ `target_sources()` + 所有 `target_*()` 命令 |
| **PATH 无关** | 开发、构建、调试、发布的全流程**不得依赖本机系统 PATH**。所有运行时路径（编译器、Qt、FFmpeg、MinGW 的 DLL 目录）必须在项目配置文件内完成注入。新机器上只需修改 `settings.json` 中的 `custom.*` 路径，其余文件全部通过 `${config:custom.*}` 引用 |

### 2.2 项目可迁移性

项目文件夹整体迁移到新机器后，需修改以下文件中的路径：

#### 2.2.1 settings.json（必须修改）

| 位置 | 数量 | 说明 |
|---|---|---|
| `cmake.configureSettings` | 4 行 | 传给 CMake 的 `-D` 参数。CMake 命令行不认识 `${config:...}` 语法，必须硬编码 |
| `cmake.environment` PATH | 1 行 | CMake 子进程环境。TRAE IDE 的 CMake Tools 实现不展开此字段中的 `${config:...}` |
| `terminal.integrated.env.windows` PATH | 1 行 | 集成终端环境。同上，TRAE IDE 不展开此字段中的变量 |

#### 2.2.2 bin/shared_env.bat（必须修改）

| 位置 | 数量 | 说明 |
|---|---|---|
| `set PATH=...` | 1 行 | 所有 `.bat` 脚本共用一个 `shared_env.bat`，PATH 只在此文件中维护 |

#### 2.2.3 自动跟随（无需手动修改）

| 文件 | 跟随方式 |
|---|---|
| `tasks.json` | `options.env.PATH` / `args` 使用 `${config:custom.mingwBase}/bin;...` |
| `launch.json` | `miDebuggerPath` 使用 `${workspaceFolder}/bin/<project>_debug.bat` |
| `CMakeLists.txt` | 通过 `cmake.configureSettings` 的 `-DQt5_DIR` / `-DFFMPEG_ROOT` 接收路径 |
| `cmake-variants.yaml` | 无路径依赖 |
| `bin/*_debug.bat` | `call "%~dp0shared_env.bat"` — 只依赖 shared_env.bat 中的路径 |
| `bin/ScreenRecorderPlayer_run.bat` | 同上 |

#### 2.2.4 为什么 settings.json 内部不能全用 `${config:custom.*}` 自引用

| 字段 | 能否用 `${config:custom.*}` | 原因 |
|---|---|---|
| `tasks.json` / `launch.json` 中的任意字段 | ✅ 能 | VS Code Task/Debug 系统原生支持 |
| `cmake.configureSettings` | ❌ 不能 | 值直接作为 `-D` 参数传给 CMake 命令行，CMake 不认识 VS Code 变量语法 |
| `cmake.environment` | ❌ 不能 | TRAE IDE 的 CMake Tools 扩展不展开此字段中的变量 |
| `terminal.integrated.env.windows` | ❌ 不能 | 同上（同属 IDE 扩展处理的环境变量通道） |

#### 2.2.5 BAT 脚本架构

```
shared_env.bat                     ← PATH 只写一次，迁移时改这一处
  ├── test_dxgi_recorder_debug.bat  → call shared_env → gdb.exe %*
  ├── ScreenRecorderPlayer_debug.bat → call shared_env → gdb.exe %*
  ├── test_ffmpeg_player_debug.bat  → call shared_env → gdb.exe %*
  └── ScreenRecorderPlayer_run.bat  → call shared_env → start "" exe
```

`%~dp0` 确保 `shared_env.bat` 被正确找到（相对调用者所在目录），不依赖工作目录。

## 3. 构建模式

支持两种构建模式：

| 模式 | 编译选项 | 用途 | Clean | Build | Rebuild |
|---|---|---|---|---|---|
| **RelWithDebInfo** | `-O0 -g`（无优化，带调试符号） | 开发阶段调试 | ✅ 默认 | ✅ 默认 | ✅ |
| **Release** | `-O2 -DNDEBUG`（O2 优化，去除断言） | 生产发布 | ✅ | ✅ | ✅ |

### 3.1 构建规则

- 构建中间产物存放在 `build/<Config>/`
- 可执行文件输出到工作区根目录的 `bin/`
- 构建完成后**不**复制 DLL 到 exe 目录；DLL 路径通过 PATH 环境变量提供
- CMakeLists.txt 使用现代 target 语法编写：
  - `add_executable(name)` 不带源码，源码通过 `target_sources()` 添加
  - 编译选项、链接选项、include 路径均通过 `target_*()` 命令设置
  - 所有目标属性集中在 `set_target_properties()` 中

### 3.2 F5 调试 — DLL 加载问题的两种解决方案

**问题**：cppdbg 调试适配器在 Windows 上无法通过 `launch.json` 的 `"environment"` / `"env"` 字段将 PATH 正确传递给目标进程，导致 F5 启动调试时出现 `0xC0000135 (STATUS_DLL_NOT_FOUND)`。

**方法 A（当前使用）：`.bat` 脚本在 GDB 启动前注入 PATH**

```
链路: cppdbg → cmd.exe(.bat) → set PATH=... → gdb.exe %* → 目标exe
```

`bin/<project>_debug.bat`（三个，每个项目一个）通过 `call "%~dp0shared_env.bat"` 共享 PATH 设置，然后 `gdb.exe %*` 透传所有调试参数。

| 文件 | 内容 |
|---|---|
| `bin/shared_env.bat` | `set PATH=...;`（PATH 集中维护，仅此一处） |
| `bin/test_dxgi_recorder_debug.bat` | `call shared_env → gdb.exe %*` |
| `bin/ScreenRecorderPlayer_debug.bat` | 同上 |
| `bin/test_ffmpeg_player_debug.bat` | 同上 |

在 `launch.json` 中指定：

```jsonc
"miDebuggerPath": "${workspaceFolder}/bin/<project>_debug.bat"
```

**方法 B（备用）：GDB CLI `set environment` + `targetArchitecture`**

```
链路: cppdbg → GDB → CLI set environment PATH=... → CreateProcess → 目标exe
```

两项配置缺一不可：

| 配置 | 作用 |
|---|---|
| `"targetArchitecture": "amd64"` | 消除 `Warning: Debuggee TargetArchitecture not detected`，使 GDB 进入稳定模式 |
| `"customLaunchSetupCommands"` | CLI 通道（非 MI）发送 `set environment PATH = ...;$env(PATH)`。GDB CLI 的 `=` 语法将整个路径值作为单个参数，分号不被截断（MI 通道会将分号解释为命令分隔符） |

切换方法：注释/取消注释 `launch.json` 中对应字段即可。

### 3.3 Release 发布流程

Release 模式的发布通过 `bin/ScreenRecorderPlayer_run.bat` 脚本实现，不使用 CMake install：

1. 编译 Release 模式，exe 输出到 `bin/`
2. `bin/ScreenRecorderPlayer_run.bat` 负责：
   - `call "%~dp0shared_env.bat"` 注入 PATH（复用共享环境脚本）
   - 使用 `setlocal` / `endlocal` 隔离环境变量变更
   - `start "" "ScreenRecorderPlayer.exe"` 启动程序后脚本立即退出

## 4. 功能需求

### 4.1 屏幕录制

| 参数 | 规格 |
|---|---|
| 录制范围 | 主屏幕，坐标原点起 |
| 录制尺寸 | 800×600 固定 |
| 帧率 | 20 fps 固定 |
| 数据格式 | BGRA（不转 YUV） |
| 压缩 | 无损压缩后立即封装 |
| 封装格式 | 由编码器决定（如 FFV1 + MKV） |
| 实现 API | AVFilterContext, AVFilter, avfilter_graph_create_filter 等 |

**RecordWidget（录制组件）**：

采用前后端分离模式：前端（RecordWidget，QWidget）整合 UI 控件，后端（ScreenRecorder，QObject）负责录制引擎。状态转移逻辑由后端掌控。

- **前端控件组**（RecordWidget）：
  - `QPushButton` — 录制控制按钮（三态切换：未录制/出错 →「开始录制」，录制中 →「停止录制」）
  - `QLineEdit` — 存放视频文件的文件夹路径（可编辑文本框）
  - `QPushButton` — 向 FileManager 发起选择存放视频文件夹的按钮，选中后回填到路径文本框
  - `QLabel` — 已录制时间显示
  - `QLabel` — 当前录制文件名显示
- **后端**（ScreenRecorder，QObject）：屏幕捕获、编码、封装的实现引擎
  - 状态机：Stopped / Recording / Error（详见《录制的状态转移.md》）
  - `startRecording()` 内部校验 Stopped 后创建输出+编码器+滤镜图→Recording；失败则→Error
  - `stopRecording()` 从 Recording 或 Error 均可进入 Stopped（退出会话）
  - 出错后立即通过 `recordError` 信号推送。录制会话不因错误自动终结（Error ≠ Stopped），TabManager 维持 RecordSession
- 文件夹路径的选择与管理委托 FileManager

### 4.2 视频播放

| 参数 | 规格 |
|---|---|
| 解码 | FFmpeg8 |
| 渲染 | Qt QOpenGLWidget，GPU 纹理上传 |
| 线程 | 读取 → 解码 → 处理 → 渲染 串行执行 |
| 速度控制 | 用户指定播放 fps（1–200），视频编码 fps 为正常速度 |

**VideoPlayer + VideoEngine（播放组件）**：

采用前后端分离模式，与录制对称。前端（VideoPlayer，QWidget）负责 UI，后端（VideoEngine，QObject）负责解码引擎和状态管理。

播放某个视频是一次有边界的会话，其生命周期状态转移全部由 VideoEngine 控制。
播放速度（fps）由前端 `QSpinBox` 获取后通过 `m_engine->setPlaybackSpeed(int)` 传入后端，后端据此计算帧间间隔。

- **前端控件组**（VideoPlayer）：
  - `QOpenGLWidget` — 视频渲染区域
  - `QComboBox` — 视频文件下拉列表（内容由 FileManager 提供）
  - `QPushButton` — 选择视频文件夹按钮（向 FileManager 发起，选中后刷新下拉列表）
  - `QPushButton` × 3 — 播放 / 暂停&恢复 / 停止
  - `QLabel` — 总时间显示
  - `QLabel` — 当前播放时间显示
  - `QSpinBox` — 播放速度选择（1–200 fps）
- **后端**（VideoEngine，QObject）：
  - 状态机：Empty / Ready / Playing / Paused / Stopped / Error（详见《播放的状态转移说明.md》）
  - 所有状态转移逻辑（openFile/play/pause/resume/stop 时的校验）由 VideoEngine 自行裁决
  - 内置有限状态机转移控制函数作为核心，用查表方式统一校验
  - 能进入 Playing 的入口（Ready→play / Stopped→play / Paused→resume）都可能因解码异常进入 Error
  - Error 的唯一出口是 stop() → Empty；Playing/Paused→stop() 进入 Stopped（会话保留）
  - 出错后立即通过 `errorOccurred` 信号推送错误信息；后端内部留存错误详情供 `getErrorString()` 查询
  - 前端不判断状态，只转发用户操作并响应信号
- 文件夹路径与文件列表的管理委托 FileManager

### 4.3 文件管理（FileManager）

FileManager 是整个程序文件夹与文件路径处理的**集中后端**，为录制和播放功能提供服务：

- 程序启动时自动以 exe 所在目录为工作目录
- 启动时在 `videodir/yyyymmdd` 下创建日期子目录
- 录制类通过 FileManager 获取输出文件夹路径、生成新文件名
- 播放类通过 FileManager 获取视频文件夹路径、视频文件列表

## 5. 非功能性需求

| 项 | 要求 |
|---|---|
| 互斥 | 录制与播放同一时间只能进行一个 |
| 性能 | 20fps 稳定录制/播放 |
| 内存 | 无泄漏 |
| 稳定性 | 无崩溃，异常正确处理 |

### 5.1 架构原则

| 原则 | 说明 |
|---|---|
| 状态归后端 | 录制和播放的状态转移逻辑、校验规则、状态存储全部由引擎类负责 |
| 前端不判断 | 前端不写 `if (state == xxx)` 来决定能不能做某事；只转发用户操作为后端方法调用，根据信号更新 UI |
| 会话互斥 | TabManager 使用独立的会话层状态空间（Idle / RecordSession / PlaySession），不与引擎瞬时状态混淆：录制在 Stopped 状态时可切到播放；播放在 Empty 或 Stopped 状态时可切到录制（详见《播放的状态转移说明.md》5.1） |

### 5.2 TabManager 与引擎层状态的对应关系

| TabManager 状态 | 含义 | 对应的引擎层条件 |
|---|---|---|
| Idle | 双方均无活跃会话 | ScreenRecorder == Stopped **且** VideoEngine == Empty |
| RecordSession | 录制会话存在 | ScreenRecorder ≠ Stopped（Recording 或 Error） |
| PlaySession | 播放会话存在 | VideoEngine ≠ Empty（Ready / Playing / Paused / Stopped / Error） |

## 6. 核心类接口定义

全局共计 **5 个**顶级自定义类（不含引擎辅助类）。

| # | 类名 | 基类 | 角色 |
|---|---|---|---|
| 1 | MainWindow | QMainWindow | 主窗口，组装所有子组件 |
| 2 | RecordWidget | QWidget | 录制前端 |
| 3 | VideoPlayer | QWidget | 播放前端 |
| 4 | TabManager | QObject | 标签页切换与互斥 |
| 5 | FileManager | QObject | 集中文件路径后端 |
| — | ScreenRecorder | QObject | 录制引擎（由 RecordWidget 持有） |
| — | VideoEngine | QObject | 播放引擎（由 VideoPlayer 持有） |

### 6.1 MainWindow

- 继承：`QMainWindow`，运行于主线程
- 持有 TabManager、FileManager、RecordWidget、VideoPlayer
- 负责 UI 组装、FileManager 的创建与分发

### 6.2 RecordWidget（录制前端，前后端整合）

- **继承**：`QWidget`
- **前端控件**：
  - `QPushButton (m_toggleRecordBtn)` — 三态切换录制按钮
  - `QLineEdit (m_folderPathEdit)` — 存放视频文件的文件夹路径（可编辑文本框）
  - `QPushButton (m_browseBtn)` — 向 FileManager 发起文件夹选择，回填路径
  - `QLabel (m_recordingTimeLabel)` — 已录制时间
  - `QLabel (m_currentFileLabel)` — 当前录制文件名
- **后端**：持有 `ScreenRecorder*`（录制引擎，纯 QObject）
  - 状态机：Stopped / Recording / Error
  - 前端不判断状态，onToggleRecord() 直接调用 m_recorder->startRecording() 或 stopRecording()
- **FileManager 依赖**：`m_browseBtn` 和 `m_folderPathEdit` 通过 FileManager 获取/设置路径

### 6.3 VideoPlayer（播放前端）

- **继承**：`QWidget`
- **前端控件**：
  - `QOpenGLWidget (m_videoWidget)` — 渲染区域
  - `QComboBox (m_fileComboBox)` — 视频文件下拉列表
  - `QPushButton (m_browseBtn)` — 选择视频文件夹按钮
  - `QPushButton (m_playBtn)` — 播放
  - `QPushButton (m_pauseResumeBtn)` — 暂停/恢复
  - `QPushButton (m_stopBtn)` — 停止
  - `QLabel (m_totalTimeLabel)` — 总时间
  - `QLabel (m_currentTimeLabel)` — 当前播放时间
  - `QSpinBox (m_fpsSpinBox)` — 播放速度 1–200
  - `QLabel (m_statusLabel)` — 状态/错误信息
- **后端**：持有 `VideoEngine*`（播放引擎，纯 QObject）
  - 状态机：Empty / Ready / Playing / Paused / Error
  - 前端所有按钮槽函数直接转发为 m_engine->play() / pause() / resume() / stop()，不自行判断
- **FileManager 依赖**：`m_fileComboBox` 和 `m_browseBtn` 通过 FileManager

### 6.4 TabManager

- 继承：`QObject`
- 与引擎层的概念层次不同：TabManager 管理的是「会话是否存在」，而非播放/录制的瞬时状态
- 状态机：
  - `Idle` — 双方均无活跃会话，标签页可自由切换
  - `RecordSession` — 录制会话存在（ScreenRecorder ≠ Stopped），锁定录制标签页，禁止切到播放；Stopped 时允许切到播放
  - `PlaySession` — 播放会话存在（VideoEngine ≠ Empty），锁定播放标签页，禁止切到录制；Stopped 时通过隐式 closeFile() 允许切到录制
- 互斥规则：只要某一方存在活跃会话，就不能切到另一方；必须等当前会话终结后才恢复 Idle

### 6.5 FileManager（集中文件后端）

- 继承：`QObject`
- 为录制和播放提供统一的文件路径服务
- 接口：`getCurrentDateDir()` / `generateVideoFileName()` / `getVideoFileList()` / `getFullPath()` / `fileExists()`
- 信号：`fileListUpdated()` / `fileError(const QString&)`

## 7. 线程架构

```
主线程 (GUI)
├── 界面事件循环
├── 录制控制信号 → ScreenRecorder 录制线程
│   ├── 屏幕捕获 (BGRA)
│   ├── 无损压缩 (FFV1)
│   └── 文件封装 (MKV)
└── 播放控制信号 → VideoEngine 播放线程
    ├── 文件读取
    ├── FFmpeg 解码
    ├── 格式转换 (BGRA)
    └── frameReady 信号 → 主线程 OpenGL 渲染
```
