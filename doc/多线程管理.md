# ScreenRecorderPlayer — 多线程管理

## 1. 线程架构

```
主线程 (GUI Event Loop)
├── ScreenRecorder 录制线程: recordingLoop() → 屏幕捕获 → 编码 → 封装
└── VideoEngine 播放线程:   playbackLoop()  → 读取 → 解码 → 格式转换
```

前后端通信基于 Qt 信号槽（`QueuedConnection`），前端不直接修改后端状态。同步机制采用 `QMutex` 保护状态块 + `std::atomic<bool>` 作为线程退出信号。

---

## 2. 问题分析：现有设计风险

### 2.1 TOCTOU 竞态（stopRecording 与录制线程）

在原有设计中，`stopRecording()` 中 `tryTransition()` 的 `load()` 和后续的 `if (m_recordState.load() == Recording)` 是两个独立操作，存在空窗：

```
主线程                              录制线程
──────────────────────────────────────────────────
tryTransition: load() → Recording
                                   setState(Error)
if (load() → Error):
    跳过 wait()              ←── 线程仍在 return 栈展开中
closeOutput()                ←── FFmpeg 资源并发访问！
```

后果：`closeOutput()` / `closeInput()` 与录制线程中的 FFmpeg 上下文产生数据竞争，轻则状态损坏，重则崩溃。

### 2.2 `m_prevState` 损坏

`stopRecording()` 中直接 `m_recordState.store(Stopped)` 绕过 `setState()`，随后 `setState(Stopped)` 读到的"上一个状态"是刚写入的 `Stopped` 而非真实的 `Recording` 或 `Error`：

```cpp
m_recordState.store(Stopped);     // 直接写入
// ...
setState(Stopped);                // setState 内: m_prevState = m_state.load() → Stopped（错误！）
```

任何依赖 `stateChanged` 信号中 prev/current 差异的逻辑都会出错。

### 2.3 录制线程错误路径无清理

```cpp
void ScreenRecorder::recordingLoop() {
    while (m_recordState.load() == Recording) {
        if (!captureFrame()) {
            setState(Error); return;    // 不做任何清理
        }
        if (!encodeFrame()) {
            setState(Error); return;    // 同上
        }
    }
}
```

配合 TOCTOU 竞态，录制线程在 `return` 栈展开过程中 FFmpeg 编码器/封装器可能处于不完整状态（如 MKV 文件尾部未写完）。

### 2.4 非原子成员变量无保护访问

`m_prevState`、`m_errorString` 在两线程间无保护读写，属于 Undefined Behavior。

### 2.5 `QThread::quit()` 对无事件循环线程无效

`m_recordThread->quit()` 对纯 `while` 循环线程是死代码——线程停止实际依赖状态变量的变化，代码意图与行为不符。

---

## 3. 解决方案

### 3.1 核心思路

1. **`QMutex` 保护状态块**：将 `m_state`、`m_prevState`、`m_errorString` 放在同一 mutex 下，保证复合操作的原子性。
2. **`std::atomic<bool>` 做线程退出信号**：录制循环高频读取时无需争锁。
3. **`stopRecording()` 采用 lock → 快照 → unlock → wait → relock → 清理 模式**：消除 TOCTOU 窗口，保障资源清理安全。
4. **所有状态写入统一经 `setStateNoLock`**：消除 `m_prevState` 损坏问题。
5. **前端只读接口**：`getRecordState()` / `getErrorString()` 内部加锁，前端不直接访问后端成员。

## 4. ScreenRecorder（录制引擎）改造

### 4.1 新增成员变量

```cpp
class ScreenRecorder : public QObject {
    Q_OBJECT
public:
    enum RecordState { Stopped, Recording, Error, Invalid };

    RecordState getRecordState() const;
    QString    getErrorString() const;

    bool startRecording();
    void stopRecording();

signals:
    void recordStateChanged(int state);
    void recordingTimeUpdated(int seconds);
    void recordError(const QString& msg);

private:
    // ---- 状态块（由 m_stateMutex 保护） ----
    mutable QMutex m_stateMutex;
    RecordState    m_state      = Stopped;
    RecordState    m_prevState  = Stopped;
    QString        m_errorString;

    // ---- 录制线程退出信号（无锁，高效轮询） ----
    std::atomic<bool> m_stopRequested{false};

    QThread*   m_recordThread = nullptr;

    // 以下方法**假定调用者已持有 m_stateMutex**
    void setStateNoLock(RecordState s, const QString& errorMsg = {});
    bool tryTransitionNoLock(RecordTransition op, RecordState& outTarget);

    // 转移矩阵（不变）
    static const RecordState transitionMatrix[3][2];

    void recordingLoop();

    // 资源管理
    void closeOutput();
    void closeInput();
    void cleanupFilterGraph();
    void cleanup();
};
```

### 4.2 转移矩阵

```cpp
const RecordState ScreenRecorder::transitionMatrix[3][2] = {
    //            Start           Stop
    /* Stopped  */{ Recording,     Stopped   },
    /* Recording*/{ Invalid,       Stopped   },
    /* Error    */{ Invalid,       Stopped   },
};
```

### 4.3 转移控制函数（持锁调用）

```cpp
bool ScreenRecorder::tryTransitionNoLock(RecordTransition op, RecordState& outTarget)
{
    outTarget = transitionMatrix[m_state][static_cast<int>(op)];
    return outTarget != Invalid;
}
```

### 4.4 状态设置（持锁调用）

```cpp
void ScreenRecorder::setStateNoLock(RecordState s, const QString& errorMsg)
{
    m_prevState = m_state;
    m_state = s;

    if (s == Error) {
        if (!errorMsg.isEmpty()) {
            m_errorString = errorMsg;
        }
        emit recordError(m_errorString);
    }

    emit recordStateChanged(static_cast<int>(s));
}
```

### 4.5 前端只读接口

```cpp
RecordState ScreenRecorder::getRecordState() const
{
    QMutexLocker locker(&m_stateMutex);
    return m_state;
}

QString ScreenRecorder::getErrorString() const
{
    QMutexLocker locker(&m_stateMutex);
    return m_errorString;
}
```

### 4.6 `startRecording()`（持锁校验 + 步骤执行）

```cpp
bool ScreenRecorder::startRecording()
{
    // === 持锁校验状态 ===
    QMutexLocker locker(&m_stateMutex);

    RecordState target;
    if (!tryTransitionNoLock(RecordTransition::Start, target)) return false;

    // === 逐步执行（仍持锁，失败设 Error） ===
    if (!openInput()) {
        setStateNoLock(Error, "无法打开屏幕捕获设备");
        return false;
    }
    if (!createOutput()) {
        closeInput();
        setStateNoLock(Error, "无法创建输出文件");
        return false;
    }
    if (!createFilterGraph()) {
        closeOutput();
        closeInput();
        setStateNoLock(Error, "无法创建滤镜图");
        return false;
    }

    m_stopRequested.store(false, std::memory_order_release);
    m_frameCount = 0;
    setStateNoLock(Recording);

    // 释放锁后启动线程
    locker.unlock();

    m_recordThread = QThread::create([this]() { recordingLoop(); });
    m_recordThread->start();
    return true;
}
```

### 4.7 `stopRecording()`（lock → 快照 → unlock → wait → relock → 清理）

```cpp
void ScreenRecorder::stopRecording()
{
    // ============ 阶段1：持锁校验并标记退出 ============
    m_stateMutex.lock();

    RecordState target;
    if (!tryTransitionNoLock(RecordTransition::Stop, target)) {
        m_stateMutex.unlock();
        return;
    }

    RecordState stateBeforeStop = m_state;

    if (stateBeforeStop == Recording) {
        m_stopRequested.store(true, std::memory_order_release);
    }

    m_stateMutex.unlock();

    // ============ 阶段2：等待线程退出（不持锁） ============
    if (m_recordThread) {
        m_recordThread->wait();
        delete m_recordThread;
        m_recordThread = nullptr;
    }

    // ============ 阶段3：持锁清理 FFmpeg 资源并设状态 ============
    m_stateMutex.lock();

    closeOutput();
    closeInput();
    cleanupFilterGraph();
    cleanup();

    m_stopRequested.store(false, std::memory_order_release);
    setStateNoLock(Stopped);

    m_stateMutex.unlock();
}
```

**阶段设计理由**：

| 阶段 | 持锁? | 原因 |
|---|---|---|
| 1 校验 + 退出标志 | ✅ 持锁 | 防止与录制线程的 `setState(Error)` 竞态 |
| 2 等待线程 | ❌ 不持锁 | `wait()` 是阻塞操作；持锁会阻止录制线程的 `setState(Error)` 获取锁，造成死锁 |
| 3 清理 FFmpeg | ✅ 持锁 | `wait()` 后线程已死，清理安全；重拿锁保证状态原子写入 |

**时序正确性——四个场景**：

```
场景A：正常停止（线程在 while 循环中）
  主: lock → 读 state=Recording → m_stopRequested=true → unlock
  录: while 看到 stopRequested → 退出循环 → 线程结束
  主: wait() 返回 → lock → closeOutput/closeInput/cleanup → setStateNoLock(Stopped) → unlock
  ✅ 无竞态，等待时无锁死

场景B：线程已出错退出（state == Error）
  主: lock → tryTransition 允许(Error→Stopped) → stateBeforeStop=Error → unlock
      不设 m_stopRequested（线程已不在 while 中）
  主: wait() 立即返回（线程已死）→ lock → 清理 → setStateNoLock(Stopped) → unlock
  ✅ 在空转 wait()，但立即返回，无死锁无竞态

场景C：录制线程正在 setState(Error) 时主线程进入 stopRecording
  主: lock（成功获取锁）
  录: lock（阻塞——主线程持锁）
  主: tryTransition → stateBeforeStop=Recording → m_stopRequested=true → unlock
  录: 拿到锁 → setStateNoLock(Error) → unlock → 线程栈展开 → return → 线程结束
  主: wait() 返回 → lock → 此时 m_state==Error → 清理 → setStateNoLock(Stopped) → unlock
  ✅ wait() 时录制线程已完成 setState 和 return，无资源竞争

场景D：并发调用 stopRecording（Qt 主线程串行，不发生）
  第二次 tryTransition → Invalid → 直接 return
```

### 4.8 `recordingLoop()`（错误路径安全退出）

```cpp
void ScreenRecorder::recordingLoop()
{
    while (!m_stopRequested.load(std::memory_order_acquire)) {
        if (!captureFrame()) {
            QMutexLocker locker(&m_stateMutex);
            setStateNoLock(Error, "屏幕捕获失败");
            return;
        }
        if (!encodeFrame()) {
            QMutexLocker locker(&m_stateMutex);
            setStateNoLock(Error, "编码失败");
            return;
        }
        // emit recordingTimeUpdated(...);
    }
    // 正常退出：线程静默结束，不改变状态
    // stopRecording() 的 wait() 之后负责清理和设 Stopped
}
```

**关键变化**：

- 循环条件从 `m_state == Recording` → `m_stopRequested`（无锁原子读取）
- 错误路径：`lock → setStateNoLock(Error) → unlock(locker析构) → return`
- 正常退出路径：**不设状态**，由 `stopRecording()` 统一处理

## 5. VideoEngine（播放引擎）改造

改造方式与 ScreenRecorder 完全对称。

### 5.1 新增成员变量

```cpp
class VideoEngine : public QObject {
    Q_OBJECT
public:
    enum State { Empty, Ready, Playing, Paused, Stopped, Error, Invalid };

    State   getState() const;
    QString getErrorString() const;

    bool openFile(const QString& path);
    bool play();
    void pause();
    bool resume();
    void stop();

    void videoInfoChanged(const VideoInfo& info);

private:

    State           m_state      = Empty;
    State           m_prevState  = Empty;
    QString         m_errorString;

    // ---- 播放线程退出信号（无锁） ----
    std::atomic<bool> m_stopRequested{false};

    QThread*    m_playbackThread = nullptr;

    // 以下方法**假定调用者已持有 m_stateMutex**
```

### 5.2 转移矩阵

### 5.4 `closeFile()`（简单状态转移，持锁完成）

```cpp
void VideoEngine::closeFile()
{
    QMutexLocker locker(&m_stateMutex);

    State target;
    if (!tryTransitionNoLock(Transition::CloseFile, target)) return;

    closeResources();
    setStateNoLock(Empty);
}
```

### 5.5 `play()`（持锁校验 + 启动线程）

```cpp
bool VideoEngine::play()
{
    QMutexLocker locker(&m_stateMutex);

    State target;
    if (!tryTransitionNoLock(Transition::Play, target)) return false;

    // Ready / Stopped → 启动播放线程（Paused → resume 不经过 play）
    if (!startPlaybackThread()) {
        setStateNoLock(Error, "解码首帧失败");
        return false;
    }

    setStateNoLock(Playing);
    return true;
}
```

### 5.6 `stop()`（lock → 快照 → unlock → wait → relock）

```cpp
void VideoEngine::stop()
{
    // ============ 阶段1：持锁校验并标记退出 ============
    m_stateMutex.lock();

    State target;
    if (!tryTransitionNoLock(Transition::Stop, target)) {
        m_stateMutex.unlock();
        return;
    }

    State stateBefore = m_state;
    bool needTerminate = (stateBefore == Playing || stateBefore == Paused);

    if (needTerminate) {
        m_stopRequested.store(true, std::memory_order_release);
    }

    m_stateMutex.unlock();

    // ============ 阶段2：等待线程退出（不持锁） ============
    if (m_playbackThread) {
        m_playbackThread->wait();
        delete m_playbackThread;
        m_playbackThread = nullptr;
    }

    // ============ 阶段3：持锁清理 + 设状态 ============
    m_stateMutex.lock();

    if (stateBefore == Error) {
        closeResources();
        setStateNoLock(Empty);
    } else {
        setStateNoLock(Stopped);
    }

    m_stateMutex.unlock();
}
```

`stop()` 的双重语义保持不变：

| 当前状态 | 调用 `stop()` 后 | 文件是否关闭 | 会话是否终结 |
|---|---|---|---|
| Playing | Stopped | 否 | 否 |
| Paused | Stopped | 否 | 否 |
| Error | Empty | 是 | 是 |

### 5.7 `pause()` / `resume()`（持锁简单转移）

```cpp
void VideoEngine::pause()
{
    QMutexLocker locker(&m_stateMutex);
    State target;
    if (!tryTransitionNoLock(Transition::Pause, target)) return;
    suspendThread();
    setStateNoLock(Paused);
}

bool VideoEngine::resume()
{
    QMutexLocker locker(&m_stateMutex);
    State target;
    if (!tryTransitionNoLock(Transition::Resume, target)) return false;
    if (!resumeThread()) {
        setStateNoLock(Error, "恢复播放失败：解码异常");
        return false;
    }
    setStateNoLock(Playing);
    return true;
}
```

### 5.8 `openFile()`（持锁校验 + 资源操作）

```cpp
bool VideoEngine::openFile(const QString& path)
{
    QMutexLocker locker(&m_stateMutex);

    State target;
    if (!tryTransitionNoLock(Transition::OpenFile, target)) return false;

    closeResources();
    if (!openAndInit(path)) {
        setStateNoLock(Empty, "无法打开文件: " + path);
        return false;
    }
    setStateNoLock(Ready);
    return true;
}
```

### 5.9 `setStateNoLock`

```cpp
void VideoEngine::setStateNoLock(State s, const QString& errorMsg)
{
    m_prevState = m_state;
    m_state = s;

    if (s == Error) {
        if (!errorMsg.isEmpty()) {
            m_errorString = errorMsg;
        }
        emit errorOccurred(m_errorString);
    }

    emit stateChanged(s);
}
```

## 6. 改造前后对比

### 6.1 成员变量迁移

| 旧实现 | 新实现 | 原因 |
|---|---|---|
| `std::atomic<RecordState> m_recordState` | `RecordState m_state` + `QMutex m_stateMutex` | 保护复合操作 |
| `m_recordState.load()` 循环条件 | `m_stopRequested.load()` | 无锁高效退出 |
| `m_recordState.store(Stopped)` 在 stopRecording | 删除，`setStateNoLock(Stopped)` 统一写入 | 消除 prevState 损坏 |
| `m_recordState.load()` 分散在各方法 | `m_state` 直接读（已持锁） | 不需要 atomic load |
| `m_recordThread->quit()` | 删除 | 无事件循环线程不需要 quit |

### 6.2 风险消除

| 风险 | 改造前 | 改造后 |
|---|---|---|
| TOCTOU 竞态 | 🔴 存在 | ✅ lock → 快照 → unlock → wait → relock |
| `m_prevState` 损坏 | 🔴 存在 | ✅ 统一经 `setStateNoLock` |
| 错误路径 FFmpeg 半损坏 | 🟡 风险 | ✅ stopRecording 在 wait() 后清理 |
| `m_errorString` 多线程读写 | 🟡 UB | ✅ mutex 保护 |
| 前端直接读写状态 | 🟢 不违反（已遵守） | ✅ 显式只读接口 `const` |

### 6.3 不变量

以下对外行为**完全不变**：

- 状态枚举定义
- 转移矩阵允许/禁止规则
- `startRecording()` / `stopRecording()` 调用约定和返回值语义
- 所有信号签名
- TabManager 通过 `getState()` / 信号判断会话层的逻辑
- 前端通过信号更新 UI 的模式

---

## 7. 设计原则总结

| 原则 | 说明 |
|---|---|
| 锁最小化 | mutex 只保护状态块；退出信号用 atomic 避免循环争锁 |
| 锁不跨等待 | `wait()` 不在持锁期间调用，防止死锁 |
| 统一写入路径 | 所有状态修改必须经过 `setStateNoLock`，杜绝直接写成员变量 |
| 前端只读 | 前端通过 `const` 成员函数 + 内部加锁读取状态，不直接访问成员 |
| 对称设计 | ScreenRecorder 和 VideoEngine 的锁协议完全一致，降低认知负担 |
